# مهمة: بناء «محرّك متابِع التلاوة الحي» (Recitation Tracker Core) — صندوق أسود

<role>
أنت مهندس خوارزميات أول متخصص في مطابقة النصوص الضبابية (fuzzy/approximate
string matching) والمحاذاة المتدفقة (online sequence alignment) للنص العربي.
أولويتك: الصحة والثبات قبل الذكاء والتعقيد. الصمت أفضل من موقع خاطئ.
</role>

<context>
نبني ميزة «التسميع بالمايك» في تطبيق مصحف: المستخدم يتلو القرآن، والتطبيق
يظلّل الكلمة المنطوقة لحظة بلحظة ويقلب الصفحة تلقائيًا. **مهمتك ليست
التطبيق، بل عقله فقط:** مكتبة صغيرة معزولة تستقبل كلمات وتُخرج موقعًا
(سورة / آية / كلمة) من بين 6,236 آية. الصفحات والتظليل والصوت يبنيها غيرك.

مخرجات التعرّف على الكلام «وسخة» دائمًا:
- كلمات ناقصة أو مُسقطة، أو زائدة غير موجودة في المصحف.
- اختلاف الإملاء: الهمزات (أ إ آ ء ؤ ئ ا)، التاء المربوطة/الهاء، الألف
  المقصورة/الياء، التشكيل، الألف الخنجرية (الرحمن/الرحمٰن)، الرسم العثماني
  مقابل الإملائي (الصلوة/الصلاة)، والمدود. تجاهل أي رموز أو أرقام لاتينية.
- تلعثم وتكرار: كلمة تُعاد، أو رجوع بضع كلمات (وقف وابتداء) ثم متابعة.
- نتائج مؤقتة (interim) تُعاد كتابتها: قد تصلك «قال» ثم تُستبدل بـ«قل» في
  الدفعة التالية، وآخر كلمة في الفرضية قد تكون ناقصة. **هذا أهم مصدر ضجيج
  فعلي** — صمّم له أولًا.
- قفز مفاجئ إلى سورة أو موضع آخر بالكامل (تقدّمًا أو مراجعةً للوراء).
- آيات متطابقة حرفيًا في مواضع عدة (فبأي آلاء ربكما تكذبان ×31، ويل يومئذ
  للمكذبين، فهل من مدكر…) ومقاطع متشابهة بين سور مختلفة.
- فواتح تُقال دائمًا وتطابق آيات فعلية: البسملة = الفاتحة 1:1 (وجزء من النمل
  27:30)، والاستعاذة ≈ النحل 16:98 (وتشبه 7:200 و41:36).
- الحروف المقطعة قد تصل منطوقة بأسمائها (الم ← «ألف لام ميم»).
- عبارات ليست من المصحف: «صدق الله العظيم» (تشبه جزءًا من 3:95)، «آمين»،
  «الله أكبر» — يجب إهمالها لا تتبّعها.

ملف المواصفات المرفق (`SPEC.md`) هو **المرجع الأعلى** للسلوك المطلوب. إذا
تعارض أي شيء هنا معه، اتبع SPEC وسجّل التعارض في README. **الطريقة
(الخوارزمية) متروكة لك بالكامل** — المطلوب هو السلوك، لا طريقة بعينها.
</context>

<interface_contract>
اللغة: TypeScript (strict)، بلا أي اعتماديات وقت التشغيل، تعمل في المتصفح
(وحبذا في Web Worker) وفي Node. نص المصحف يُمرَّر كبيانات (Tanzil
simple-clean بالعدّ الحفصي — تحقق من ترخيص المصدر)، والمكتبة لا تجلبه أبدًا.

```ts
type Position = { surah: number; ayah: number; word: number }; // كلها من 1، وword بتقسيم المصحف المعروض (§ترقيم)
type TrackerState = "SEARCHING" | "CANDIDATE" | "LOCKED" | "LOST";
type TrackerEvent =
  | { type: "position"; pos: Position; confidence: number; state: TrackerState;
      detail: "advance" | "repeat" | "restart" | "skip_forward";
      tentative: boolean;          // آخر كلمة قد تكون ناقصة (interim)
      next?: Position;             // الكلمة المتوقعة التالية (للواجهة)
      candidates?: Position[] }    // عند الالتباس الحقيقي بدل التخمين
  | { type: "jump"; from: Position | null; to: Position; confidence: number;
      detail: "jump_in_surah" | "jump_surah" }
  | { type: "revise"; replaced: Position | null; pos: Position;   // تصحيح بأثر رجعي
      reason: "basmala_is_fatiha" | "duplicate_resolved" }
  | { type: "surah_end"; surah: number }                           // 114 = نهاية المصحف
  | { type: "lost"; last: Position | null }
  | { type: "preamble"; kind: "istiadha" | "basmala" }; // فاتحة تم تجاهلها

interface RecitationTracker {
  // words: الفرضية الحالية كاملةً لهذه الجملة (وليست فرقًا). isFinal=false
  // تعني أنها ستُستبدل/تُمدَّد في الاستدعاء القادم — كرّر نفس المدخل أو نموه
  // (idempotent) بأمان دون تحريك خاطئ. timestampMs لساعة المتصفح (للترتيب).
  push(words: string[], opts: { isFinal: boolean; timestampMs: number }): TrackerEvent[];
  // بعد isFinal=true يبدأ الاستدعاء التالي فرضية جديدة (حدود الجمل صريحة).
  getState(): { state: TrackerState; pos: Position | null; confidence: number };
  reset(hint?: { surah?: number; ayah?: number }): void; // المستخدم فتح صفحة = أولوية قوية
  snapshot(): string; restore(s: string): void;         // حالة قابلة للتسلسل
}
declare function createTracker(quranData: QuranWords): RecitationTracker;
```

- `QuranWords`: صِف الصيغة التي تحتاجها (كلمات مقسّمة لكل آية) ووثّقها، واكتب
  سكربت تحويل من ملف البيانات المرفق إن لزم.
- `confidence` بين 0 و1 **ومعناه موثّق** في README (ماذا يعني 0.9 مقابل 0.6).
- لا تُرجع موقعًا لست واثقًا منه. لا تعدّل SPEC ولا ملف القرآن الأصلي.
</interface_contract>

<word_segmentation>
`word` في الموقع يجب أن يطابق **تقسيم كلمات المصحف المعروض في الواجهة**، لا
تقسيم نص البيانات الداخلي — وإلا انزاح التظليل بصمت. المشكلة حقيقية: «يا
أيها» كلمتان في النصوص الإملائية (143 موضعًا في بياناتنا) لكنها كلمة واحدة
مرسومة (يَٰٓأَيُّهَا) في المصحف العثماني المعروض. القاعدة:
- المطابقة الداخلية تتم على نسخة مطبّعة، **ومعها جدول ربط صريح** بين تقسيم
  المطابقة وتقسيم العرض لكل آية يختلفان فيها.
- `word` الخارج من المحرك هو فهرس كلمة العرض (1-based)، لا فهرس المطابقة.
- اختبار إلزامي: تلاوة مقطع فيه «يا أيها» والتحقق أن التظليل على الكلمة
  المعروضة الصحيحة لا جارتها.
(قرار يخص صاحب التطبيق: أي تقسيم تُبرزه الواجهة — طبّق المحرك عليه. في
تطبيقنا الحالي: صور صفحات بخط مصحف المدينة + عدّ الكلمات بتقسيم النص
البياني، والتظليل تقدير تناسبي — أي أن `word` عندنا = فهرس كلمة النص
البياني بالتعريف.)
</word_segmentation>

<required_behavior>
1. **البحث الأولي (SEARCHING→CANDIDATE→LOCKED):** بلا معرفة سابقة، حدّد
   الموقع بأقل كلمات ممكنة، على قوة الدليل لا عدد ثابت («قل هو الله أحد»
   تُثبّت سريعًا لفرادة كلماتها). كلمة أو كلمتان عامّتان لا تُثبّتان أبدًا. مع
   تعدد الاحتمالات ابقَ CANDIDATE وأخرج `candidates` حتى تأتي كلمات فارقة
   تميّز موضعًا واحدًا. يجب أن يعمل التثبيت من **منتصف** الآية لا أولها فقط.
2. **التتبّع (LOCKED):** تقدّم كلمة بكلمة مع المنطوق، شاملًا عبور حدّ الآية
   **حتى القصيرة جدًا (1–3 كلمات: طه، يس، مدهامتان، ماكثين فيه أبدا)** — يجب أن
   يلتقطها منتصف التدفق لا بعد انتهائها. وعبور حدّ السورة (آخر الفاتحة ←
   البقرة) طبيعيًا، مع حدث نهاية السورة (`surah_end`)، ونهاية المصحف بعد
   الناس (`surah_end` بالسورة 114).
3. **الكلمة المفردة لا تقفز فوق آية كاملة:** أقصى ما تصل إليه الكلمة الواحدة
   هو أول كلمة في الآية التالية مباشرة — لا يجوز تخطّي آية بأكملها على كلمة
   مشتركة واحدة (مصدر قفزات 18:5←18:7).
4. **التسامح:** كلمة ساقطة (تقفز اللاحقة بسلاسة)، دخيلة، أو مستبدلة بمشابهة
   نطقًا — خطأ واحد لا يُسقط التثبيت.
5. **التكرار والرجوع:** تكرار دقيق لكلمة/كلمتين (تصحيح/تجويد) يرجع بدقة
   ولا يُفقد التثبيت ولا يُحتسب دليل ضياع. أما إعادة الآية كاملة للحفظ فهي
   حدث `restart` ويرجع الموقع لأولها. (تكرار ضبابي مشابه لكلمات أخرى يُعامل
   كضجيج لا كرجوع.)
6. **النتائج المؤقتة:** استبدال الفرضية يجب ألا يرجّح الموقع ذهابًا وإيابًا؛
   لا تتقدم على كلمة مؤقتة ضعيفة المطابقة؛ ضع `tentative: true` حتى التثبيت.
7. **القفز (للأمام وللمراجعة الخلفية):** يحتاج دليلًا أقوى من التقدم العادي
   (عدّة كلمات متتالية من الموضع الجديد، لا كلمة شائعة مفردة). أثناء جمع
   الدليل يبقى الموقع ثابتًا بلا ارتجاج، ثم قفزة واحدة حاسمة مع حدث `jump`.
   **ممنوع التذبذب** بين موقعين في تحديثات متتالية. والمراجعة للوراء
   (إنهاء 18:42 ثم إعادة 18:37) يجب أن تُكتشف وتُتبَع لا أن تتجمد في الأمام.
8. **المكرر حرفيًا:** مع تثبيت سابق يكون الموقع هو **التكرار التالي** لا
   الأول؛ وبلا سياق يبقى الالتباس معلنًا (`candidates`) ويُحسم **بأثر رجعي**
   من الكلمات اللاحقة (عبر حدث `revise` يصحّح الموقع السابق علنًا).
9. **المتشابهات بين السور:** السياق الحالي له أفضلية ولا يُترك إلا بكلمات
   فارقة تدل على غيره.
10. **البسملة:** في أول الفاتحة هي 1:1. في غيرها حدث `basmala` بلا تثبيت على
    الفاتحة، ويبقى المحرك بانتظار ما بعدها؛ فإن جاء «الحمد لله رب العالمين»
    رُجّح أنها الفاتحة **بأثر رجعي** (عبر حدث `revise`). استثناء التوبة (بلا
    بسملة): بسملة ثم «براءة من الله» → تُتتبَّع 9:1 دون احتساب البسملة جزءًا
    منها.
11. **الاستعاذة:** حدث `istiadha` بلا نقل إلى 16:98 رغم التشابه؛ وإن تُلي نص
    16:98 فعلًا ضمن سياق السورة 16 فيُتتبّع كالمعتاد.
12. **الضياع (LOST):** بعد **8 كلمات متتالية غير مطابِقة** (المقياس بعدد
    الكلمات لا بالصمت ولا بالساعة) → LOST بلا موقع عشوائي، ثم عودة للبحث.
    عبارات مثل «صدق الله العظيم» و«آمين» تُهمَل دون فقدان التثبيت.
13. **الحتمية:** نفس المدخلات → نفس المخرجات دائمًا (لا عشوائية، لا اعتماد
    على الساعة إلا للترتيب).
</required_behavior>

<tests>
ابنِ **أولًا** مولّد اختبارات: يأخذ مقاطع عشوائية حقيقية من المصحف ويُفسدها
(إسقاط 5–15%، استبدال 5–10%، اختلاف إملائي، تلعثم، كلمات دخيلة، إعادة،
قفزات) **ببذرة ثابتة (seeded)** لتكون قابلة للإعادة، ومع حالات ذهبية يدوية
لكل بند في السلوك أعلاه. ثم نفّذ المحرك، وقِس، وكرّر. السيناريو = تسلسل
استدعاءات `push` (بما فيها مؤقتة تتغير 3 مرات قبل النهائية) + التوقّع
(الموقع النهائي، الأحداث المهمة، وما يجب ألا يحدث). تغطية إلزامية:
- تلاوة نظيفة لعدة آيات عبر حدود سورتين؛ ونفسها مع 20% إسقاط و10% زوائد
  وأخطاء همزات وتاء مربوطة.
- عبور آية قصيرة (3 كلمات) منتصف التدفق؛ وكلمة مفردة لا تتجاوز آية أبدًا.
- تلعثم: تكرار كلمة 3 مرات، ورجوع 4 كلمات ثم متابعة؛ وإعادة آية كاملة (restart).
- نتيجة مؤقتة تتغير 3 مرات قبل النهائية.
- قفز للأمام (البقرة ← الملك) وقفز مراجعة للوراء (18:42 ← 18:37).
- كلمة شاذة واحدة وسط ثبات (بلا قفز).
- الرحمن: تلاوة 55:15 ثم 55:16 — يجب أن تكون 55:16 (التكرار الثاني، لا
  55:13 الأول). (ملاحظة تحقق: 55:13 هو أول تكرار فعلًا — لهذا صُمم الاختبار
  على الثاني لا الأول — و55:15 و55:17 و55:24 ليست مواضع تكرار أصلًا.)
  وبدء بـ«فبأي آلاء ربكما تكذبان» وحدها → CANDIDATE لا تخمين.
- آية الكلمة الواحدة: تلاوة «مدهامتان» وحدها → 55:64 (أفضل اختبار للبند 2
  من كلمة واحدة حقيقية، لا حرف مقطع).
- استعاذة + بسملة + بداية الكهف → preamble ثم LOCKED على 18:1 (لا 1:1 ولا 16:98).
- بسملة ثم «الحمد لله رب العالمين» → الفاتحة فعلًا (بأثر رجعي).
- بسملة ثم «براءة من الله ورسوله» → 9:1 (التوبة بلا بسملة؛ لا تُحتسب البسملة
  من الآية).
- الحروف المقطعة منطوقة في أول البقرة («ألف لام ميم» → 2:1).
- كلام خارج القرآن 15 كلمة → LOST دون موقع خاطئ.
</tests>
