# Audit and rebuild, 2026-10-12

The audit covered the whole app: the recite feature, graphics and overlay geometry, the layout on phones, the server, and the claims in `PROJECT_REPORT.md`. All findings below were checked in headless Chrome and with Node tests, not by reading code alone.

## 1. Recite feature: rebuilt (engine v3)

The new design is documented in `docs/RECITE_ALGORITHM.md`.

**Held-out benchmark** (`node tests/benchmark.js`): the same fake Chrome event stream, the real corpus, and seeds never used for tuning.

| scenario | v2.9.2 accuracy | v3 accuracy | false jumps v2 → v3 | flip-flops v2 → v3 |
|---|---|---|---|---|
| clean recitation | 83.0% | **99.0%** | 14 → 0 | 4 → 0 |
| noisy (drops, inserts, misspellings, merges, stutters) | 65.9% | **93.8%** | 10 → 0 | 4 → 0 |
| noisy + Android re-sends | 57.3% | **93.8%** | 47 → 0 | 13 → 0 |
| jump to another place | 60.2% | **93.2%** | 10 → 0 | 5 → 0 |
| jump + noise | 50.4% | **87.1%** | 9 → 0 | 4 → 0 |
| cold start mid-ayah, wrong page open | 62.9% | **94.6%** | 0 → 0 | 0 → 0 |
| 15 words of off-Quran speech | 58.6% (70 wrong moves) | **97.4% (1)** | 27 → 0 | 6 → 0 |

- **Locking.** After a real jump, v3 locks in a median of 4 words; v2 needed 10, and 16 of its runs never locked. When the first 4 words are unique in the Quran, v3 locked within 4 words in 50/50 cases; v2 managed 31/50.
- **Confidence is now a calibrated probability.** In the 0.45–0.70 band the shown position is correct 74% of the time, at 0.70–0.90 85%, and at 0.90 or above 99.2%.
- **Speed.** One live speech event costs p50 about 1 ms, p95 about 8 ms and p99 about 10 ms on this laptop.
- **Golden cases.** 38 of 38 pass (`node tests/run_tests.js`). They include every scenario in the recite-algorithm prompt:
  - short ayahs mid-stream (18:3, مدهامتان);
  - the Rahman refrain resolving to 55:16, not 55:13;
  - isti'adha + basmala + al-Kahf;
  - basmala → al-Fatiha and basmala → at-Tawba;
  - all three forms of the muqatta'at;
  - stutters and restarts;
  - forward and backward jumps;
  - صدق الله العظيم;
  - off-Quran speech.

### Bugs found in v2 (all gone in v3)

1. **13 stacked special-case rules.** Each was a patch for one screenshot, and they interfered with each other. This root cause produced most of the "random jump" reports.
2. **Interim revisions were appended as new words.** For example قال → قل left both words in the stream. The follower then read them as a repeat or as backward drift.
3. **Android cumulative re-sends** duplicated whole utterances: 47 false jumps in the benchmark.
4. **Browser ASR and the Whisper server both fed one stream at the same time**, so late text was consumed twice.
5. **Confidence was a constant** of 92% while following.
6. **A multi-ayah query landed on the first ayah**, not the last: «قل هو الله احد الله الصمد» → 112:1.
7. **The "84 green tests" did not exist** in the project folder. Real tests now live in `tests/`.

### UI bugs around the recite feature (fixed in `index.html`)

8. **Highlight race.** The detection handler drew the highlight after a delay: 90 ms after a page turn and 25 ms otherwise. An older update could therefore land after a newer one and overwrite it. The visible symptom: after a jump, the spotlight stayed on the previous ayah.
9. **Stale highlights after a page turn.** Turning the page never cleared the old page's highlight boxes. They stayed drawn over the new page.
10. **Spotlight flicker.** The spotlight element was recreated for every word, so its glide animation never ran and the ayah box's pulse restarted each time. Now one element glides between words.
11. **The active word was hidden behind the dock.** The page now auto-scrolls to keep the active word above the dock.
12. **Switching from two-page to single-page view** jumped to the right-hand page and lost the highlighted ayah.
13. **The basmala had no representation.** It now shows as «البسملة», with no word box.

## 2. Graphics and geometry (fixed)

14. **The card shape did not match the images.** The card used the coordinate system's shape (1260×1890) while the images are 700×1100, so the image was letterboxed inside the card and every overlay was offset.
15. **Hand-tuned offsets were wrong in x.** The constants (`+50`, `-40`) were copy-pasted into three functions: ayah highlight, word spotlight and click-to-ayah. I measured the real mapping from the page images (4,306 line ends on 151 pages, error about 2 px):
    - x was off by up to about 20 px at the page edges;
    - y was already right, within about 3 px.

    All three functions now share one mapping (`MUSHAF_MAP`), and the card has the image's exact aspect ratio. On page 293, 127 of 127 word centres map back to their own ayah.
16. **Word boxes were guesses.** The ayah rectangles used to be split in proportion to letter counts, so boxes straddled two words. `scripts/build_word_boxes.py` now measures every word on the page images: it finds ink gaps, then a dynamic program chooses the cuts. That gives measured boxes for 6,227 of 6,236 ayahs (`data/word_boxes.js`, 0.85 MB). Known weak spot: words starting with a detached «إ» are sometimes split.
17. **Phone layout was broken.** The header stayed one row about 860 px wide on a 390 px screen, so the whole page scrolled sideways and the content started off-screen. The header now wraps and uses icon buttons.
18. **"فتح ملف PDF" was a dead link.** The PDF is not in the folder. The button now hides itself when the file is missing.

## 3. Server (fixed)

19. **`recite_server.py` was single-threaded.** One stalled connection froze every request. It happened during this audit: the app on :8001 stopped loading entirely. The server is now threaded.
20. **It used the `cgi` module**, which was removed in Python 3.13. It now uses a stdlib multipart parser, tested on binary data.

> **Your running server on port 8001 is still the OLD hung process.** Close its window, or run `taskkill /PID 13996 /F`, then start it again.

## 4. Not done yet: decisions for you

| # | item | recommendation |
|---|---|---|
| A | **Acoustics.** Chrome's ar-SA recognizer hears melodic tajweed badly. This is the biggest remaining quality limit: v3 holds still instead of jumping, but it cannot follow words it never hears. | Run a Quran-trained Whisper **in the browser**: `tarteel-ai/whisper-base-ar-quran` as ONNX (the community build `iqbalaesthetic/Basira`, Apache-2.0), through transformers.js in a Web Worker, with rolling-window streaming. It needs no server and works offline after a one-time ~100 MB model download (int8/WASM). It would feed the same v3 tracker. **This needs your OK for the download.** |
| B | Real recordings test set | Log real Web Speech sessions with the true position into `tests/real/`, so the benchmark is not only synthetic. |
| C | **Git root is the parent folder** `Default Project`, which contains unrelated ATAM files and has no commits. | Run `git init` inside `quran-mushaf-app`, with a `.gitignore` for `pages/` (60 MB) or Git LFS. |
| D | Leftovers: `index.backup-before-recite-rebuild.html` (237 KB), the empty `assets/css/`, and docs written for v2 (`RECITE_FEATURE_SPEC.md`, `RECITE_HIRING_PROMPT.md`) | Delete them or archive them. The hiring prompt is obsolete now that v3 exists. |
| E | Desktop layout: about 470 px of player and navigation panels sit above the page, so only half a page is visible while reciting. | Add a "reading mode" that collapses the panels while the mic is on. |
| F | Tafsir sources other than al-Muyassar load from the internet (spa5k, quranenc), although the instructions say the app works fully offline. | Not audited in depth. Bundle them, or label them as online. |

## 5. How to verify

```
node tests/run_tests.js          # 38 golden cases
node tests/benchmark.js          # old vs new, held-out seeds (--tune for tuning seeds)
node tests/trace.js 293 "الحمد لله الذي انزل"   # belief trace, word by word
python scripts/build_word_boxes.py               # rebuild measured word boxes
```

In the browser console, `ReciteByMic.version` should print `3.0.0-hmm`.
